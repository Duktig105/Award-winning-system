# 技能树三级结构说明

> 依据：`sql/skill_tree_seed.sql`（三级技能树种子数据）、`HonorSystemService.studentSkillTree()/buildTree()`（解锁判定逻辑）、前端 `SkillStarMap.vue`（星图分层渲染）。

## 一、总体结构

技能树为 **三级层级结构**，存储于 `skill_tree_node` 表，通过 `parent_id` 建立父子关系，`level` 字段标记层级：

```
中心核心（方向中枢：skill_category，共 8 大方向）
   │
   ├── 一级 · 方向域（level=1）──── 挂在方向核心之下
   │        │
   │        ├── 二级 · 技能域（level=2）──── 挂在方向域之下
   │        │        │
   │        │        └── 三级 · 技能星点（level=3）──── 挂在技能域之下
   │        └── 二级 · 技能域 ……
   └── 一级 · 方向域 ……
```

## 二、各层级定义

### 一级 · 方向域（level = 1）

| 属性 | 取值 |
|---|---|
| `parent_id` | `NULL`（直属于方向核心） |
| `skill_id` | `NULL`（不绑定具体技能） |
| `icon` | 有专属图标（Monitor / DataAnalysis / Briefcase 等） |
| `unlock_threshold` | 0~2（按 **已验证技能项数量** 计数解锁） |

**判定逻辑**：无 `skill_id` 的节点，用学生 **已验证技能总项数（verifiedCount）** 与 `unlock_threshold` 比较，达标即点亮。

**语义**：代表某方向下的一个能力大分支，如「编程基础」「算法能力」「科研素养」。

### 二级 · 技能域（level = 2）

| 属性 | 取值 |
|---|---|
| `parent_id` | 一级方向域的 `node_id` |
| `skill_id` | 绑定具体技能（`skill` 表） |
| `unlock_threshold` | 0~150（按该技能的 **经验值 skillExp** 解锁） |

**判定逻辑**：有 `skill_id` 的节点，用学生在该技能上的累计经验值与 `unlock_threshold` 比较，达标即点亮。

**语义**：方向分支下的一项具体能力域，如「面向对象」「UI设计」「答辩技巧」。

### 三级 · 技能星点（level = 3）

| 属性 | 取值 |
|---|---|
| `parent_id` | 二级技能域的 `node_id` |
| `skill_id` | 绑定具体技能（通常与父域同 `skill_id`） |
| `unlock_threshold` | 较高（60~150 经验），代表该方向的 **高阶/实战能力** |

**语义**：技能域之上的进阶成就，如「设计模式」「算法竞赛实战」「高水平论文」「系统集成」。

## 三、解锁规则汇总（`buildTree()`）

```
skill_id != null → unlocked = (该技能累计经验值 >= unlock_threshold)
skill_id == null → unlocked = (已验证技能项总数 >= unlock_threshold)
```

即：**方向域看"验证技能数"，技能域/星点看"技能经验值"**。经验值来源于获奖审核通过后的积分入账。

## 四、种子数据中的三级划分明细

### 方向1 · 编程与开发（category_id=1）

| 一级（方向域） | 二级（技能域） | 三级（技能星点） |

| 编程基础 | 编程入门(0)、面向对象(30)、项目开发(40) | 设计模式(70) ← 挂在「面向对象」下 |
| 算法能力 | 排序与搜索(10)、动态规划(80) | 算法竞赛实战(150) ← 挂在「动态规划」下 |
| 项目工程 | 项目协作(20)、独立项目(120) | — |

| 数据分析 | 数据清洗(20)、统计推断(60) | — |
| 学术写作 | 论文结构(30)、建模论文撰写(80) | — |

### 方向3 · 设计与创意（category_id=3）
